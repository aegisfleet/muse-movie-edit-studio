# 設計メモ (docs/DESIGN.md)

本リポジトリの設計判断と、その根拠を記録する。

## 成果物仕様

- `outputs/final.mp4`: 1080×1920 (9:16)、30fps、合計尺は YAML の `project.duration_sec`（標準 30.0 秒 = 900 フレーム）、H.264 / AAC 48kHz

## 決定事項

### 1. 設定 YAML を唯一の真実とする

- Remotion コンポーネント内に動画固有のテキストを直書きしない。`run_pipeline.py` が YAML から `public/project_config.json`（開始・終了フレーム計算済み）を生成し、コンポーネントはそれをループ描画する
- 理由: エージェントが編集するのは YAML だけで済み、TypeScript の改変ミスによる合成破綻が起きない

### 2. エンコーダは実行環境で自動選択する

- `scripts/run_pipeline.py` の `select_video_encoder()` が、NVIDIA GPU デバイスの実在を確認して NVENC / libx264 を切り替える。環境変数 `VIDEO_ENCODER=nvenc|x264|auto` で上書き可能
- 理由: ffmpeg のエンコーダ一覧に `h264_nvenc` が載っていても、GPU が無い環境（Muse VM、CI、一般的なクラウド VM）では実行時エラーになる。NVENC 前提の実装では、この環境では動かない

### 3. ナレーションは Muse の Meta AI TTS を第一候補とする

- `scripts/generate_narration.py` がバックエンドを自動選択する。Muse 環境（`/opt/hatch/bin/tts` が存在）では Meta AI ボイスで合成し、それ以外では edge-tts（日本語ボイス）を使う
- 理由: ローカル TTS モデルはモデル本体と参照音声の別途管理が必要で、軽量な VM では実行も重い。Meta AI TTS は Muse 環境に組み込み済みで追加セットアップが不要。固定ボイス ID を使うことで「シーンごとに別人の声になる」問題を避ける
- 尺ガードレール（無音トリム + `atempo` 圧縮 + 末尾フェード）で、ナレーションがシーン尺を超えないことを保証する

### 4. 音楽 (BGM) は生成 AI に寄せない

- BGM は実音サンプラー + DSP の `generate_sampler_bgm.py`、または素材持ち込みとする
- 理由: Meta の生成モデルには音楽のみを単独生成する経路がない（映像付き短尺クリップの生成音はあるが、BGM トラックとして分離できない）。DSP 生成は再現性があり、音響品質の設計（リバーブ、ディレイ、ヒューマナイズ）もコードとして管理できる

### 5. 検証はローカル CV で行い、LLM の目視に依存しない

- Gate 1（レンダリング前）と Gate 2（最終成果物）で `verify_composition.py` が被写体の中央オフセット、サイズ占有率、鮮鋭度を判定する
- Muse 環境では補助として、エージェントが抽出フレーム画像を数枚だけ目視確認する運用も可能だが、主判定はローカル指標に置く

### 6. 素材と生成物は Git 管理しない

- `inputs/`、`public/audio/`、`outputs/`、モデル重み（`*.pt`）は `.gitignore` で除外する。リポジトリはコードと設定（YAML / JSON）のみを管理する
- Muse 環境では素材の受け渡しをチャット添付、写真ライブラリ、接続デバイス経由で行い、作業コピー内の `inputs/` に配置する
- ただしチャット添付には上限がある（web版: 動画 約100MB、その他 約25MB）。100MB を超える素材は Google Drive 等の外部ストレージ経由とし、Muse が連携または共有リンクで `inputs/` にダウンロードする。GB 級の GoPro 原画はこの経路が前提になる

### 7. プロキシは標準手順から外す (検証済み)

当初は「解析はプロキシ、出力は原画」の二段構えを標準とする案だったが、実測の結果、標準手順には含めないことにした。`analyze_subject.py --proxy` の実装自体は任意オプションとして残す。

- 実測 (2026-10-23、4K HLG 260秒素材・2 vCPU): プロキシ生成は初回のみ約10.5分 (全フレームのデコードが律速)。生成後の解析は約30秒 (原画直接 3分42秒の約1/7.5)、Step 1 レンダリングはプロキシから 162.8秒 vs 原画から 423.6秒 (約2.6倍)
- それでも損益分岐は同一素材で 解析 約4回 / Step 1 約3回 以上の反復が必要で、通常の1本制作 (解析1回 + 確認は Gate 1 + 本番レンダー1回) では生成コストが上回る
- 「軽量版で確認してから高解像度版を出す」役割は、既存の Gate 1 (原画に対する構図シミュレーション、約30秒) が既に担っている。Remotion 工程 (約466秒) は入力元に依存しないため、プロキシ化しても縮まらない
- したがって標準の軽量化手段はサンプリング間隔の調整とし、プロキシは長時間素材を多数回試行する場合の例外手段とする。ハイライト選定の顔ぶれは両方式で概ね一致したが、品質スコアの絶対値は解像度で変わるため方式間で比較しないこと

## Muse 環境の実測値 (2026-10-23)

- OS: Ubuntu 24.04 (x86_64)、2 vCPU、RAM 7.7GB、ディスク 100GB
- Node.js 24.22.1 / npm 10.9.4 / Python 3.12.3
- ffmpeg 8.1.2: `zscale` / `xfade` / `tonemap` / `libx264` あり。`h264_nvenc` はビルドに含まれるが GPU デバイスなし
- 日本語フォント: Noto CJK 導入済み
- Remotion のレンダリングには Headless Chrome が必要。環境に無い場合は Remotion が初回に自動取得する
- 検証の実測 (2026-10-23、テストパターン素材 6 秒・単一シーン): Step 1 (ffmpeg / libx264) 約 15 秒、Step 2 (Remotion 180 フレーム、初回バンドル・ブラウザ取得込み) 約 95 秒、出力は 1080×1920 / 6.000 秒で仕様一致。`tsc --noEmit` も通過。30 秒本番 (900 フレーム) のレンダリングは概ね 5 から 8 分が見込み
- 検証で判明した不具合 2 件を修正済み: (1) SDR 入力を HLG 用 zscale チェーンに通すと "no path between colorspaces" で失敗する → 転送特性でチェーンを分岐。(2) project_config.json の型推論が設定内容に依存し、任意項目 (narration 等) で型エラーになる → scenes / theme を any として扱い、コールバック引数に型注釈を付けた

## 制作実績 (2026-10-23、GX010100.MP4 から30秒ショートを制作)

- 素材: GoPro 4K HLG (3840×2160 / 29.97fps / 260.6秒 / 1.42GB) を Google Drive 経由で取得し MD5 一致を確認
- 被写体解析 (YOLOv8n、CPU): 原画直接・間隔3秒 (87サンプル) で 3分42秒。間隔1秒では素材の実時間を大幅に超える見込みだったため、運用基準 (処理が実時間を超えるなら間隔を広げる) に従い3秒を採用した。プロキシ解析の実測は決定事項 7 を参照
- シーン選定は解析の品質スコア上位区間を下敷きに、エージェントの目視 (候補フレーム確認) で2シーンを差し替えた (後頭部中心の区間 → 笑顔のドアップ等)。数値スコアと目視の併用が有効だった
- Gate 1 は調整2回で全シーン PASS。Gate 2 は意図したドアップ2シーンが "Too close" WARNING (被写体は正中央) で、目視確認の上で採用した
- ナレーション: Meta AI TTS で5本生成 (各2.4から3.9秒、シーン尺内に収まる)。声は avocado_v2 の MAI_01 (F0中央値 274Hz) と MAI_03 (同 214Hz、既定) の2種のみ有効で、他の ID は MAI_03 にフォールバックすることを確認した
- パイプライン全体 (Step 1 + Remotion 900フレーム) は 14分50秒。成果物は 1080×1920 / 30.06秒 / 音声ピーク -4.8dB
- SD 出力の速度検証 (540×960、Step 1 は project.resolution、Remotion は output_scale 0.5 で出力。run_pipeline.py が設定解像度に従うよう改修した): Step 1 は 342.2秒 (HD 423.6秒、19%短縮に留まる。4K 入力のデコード+トーンマップが律速で、出力解像度を下げても効きにくい)。Step 2 は 170.2秒 (HD 約466秒、約2.7倍)。全体 512.4秒 (HD 890秒の約1/1.7)。ファイルサイズは 29.3MB (HD 73.8MB)。画質はテロップ等の合成要素は鮮明だが被写体の毛並みの解像は HD に劣るため、SD は確認・プレビュー用途が主で、最終納品は HD が前提
